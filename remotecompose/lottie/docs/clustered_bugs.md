## Part I: AST Schema & Deserialization Bug Clusters (P1 Parser Strictness)

### Bug #1: Cluster S2: Split-Dimension Position Property Omitting 'a' Discriminator
- **Category**: AST Deserialization / Schema Compatibility
- **Severity**: P1 (Blocks raw JSON ingestion without preprocessing)
- **Affected External Assets (3)**:
  - `hamburger_arrow` ([Source URL](https://raw.githubusercontent.com/airbnb/lottie-android/master/sample/src/main/res/raw/hamburger_arrow.json)) — Raw Error: `SerializationException: Position property missing required 'a' field per Lottie schema`
  - `lottielogo` ([Source URL](https://raw.githubusercontent.com/airbnb/lottie-android/master/sample/src/main/res/raw/lottielogo.json)) — Raw Error: `SerializationException: Position property missing required 'a' field per Lottie schema`
  - `CheckSwitch` ([Source URL](https://raw.githubusercontent.com/airbnb/lottie-android/master/snapshot-tests/src/main/assets/Tests/CheckSwitch.json)) — Raw Error: `SerializationException: Position property missing required 'a' field per Lottie schema`
- **Technical Root Cause**:
  Position properties with split dimensions ('s': true, 'x'/'y') or un-animated defaults omit top-level 'a' field in BasePositionPropertySerializer (SerializationException: Position property missing required 'a' field per Lottie schema)
- **Recommended Fix in `remotecompose/lottie`**:
  Update `BasePositionPropertySerializer` to support split-dimension position objects (`"s": true`, `"x"`, `"y"`) and default `"a"` to `0` when omitted on static coordinate arrays.
