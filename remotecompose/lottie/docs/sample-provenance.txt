CC0 LOTTIE TEST FIXTURES
=======================

Separate generated geometry oracle (not one of the CC0 preview assets):
src/test/resources/zigzag-reference.json contains simple paths authored for these
tests and their computed zigzag coordinates. tools/generate_zigzag_reference.mjs
executes ZigZagModifier.js and PolynomialBezier.js from lottie-web v5.12.2 to
regenerate it. No production Kotlin is used in that calculation, and the source
JavaScript is not bundled with the generated fixture. Normal Gradle tests read
the checked-in JSON offline; only explicit regeneration needs network access.
The fixture includes 32 static cases and 20 motion cases with 11 frames each,
including point-type holds and interpolated transitions through the smooth value.

src/test/resources/rounding-reference.json contains 10 playback scenarios with
11 frames each. tools/generate_rounding_reference.mjs runs pinned lottie-web
RoundCornersModifier.js on authored paths and independent analytic unrounded
polystar vertices. No production Kotlin is used. It covers live radii, moving
paths, sharpness changes, open endpoints, duplicate vertices and polystar topology.

src/test/resources/offset-reference.json is separate audit data generated by
tools/generate_offset_reference.mjs from the same pinned web version. It contains
36 static cases and 36 motion scenarios, including curved offsets not yet
implemented by RC. It is not a passing-test manifest. The active polygon-offset
tests instead use independent analytic circles, polygons and half-plane
intersections; R28 records why some web reference results are not used as oracles.

Each fixture has a still and animated preview in Cc0LottiePreviews.kt.
These exercise temporal/spatial easing, color, gradient alpha, multidimensional
properties, hold keyframes, and precomposition time stretch. Rendering a fixture
does not alone establish reference-renderer parity; pixel tests do that separately.
